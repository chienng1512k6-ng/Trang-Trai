## Diagnosis and hit-test audit

The owner confirms FIX-001 passes on real iPhone Safari: Attack center/text,
10 taps, joystick + Attack, outside release, app switching and camera zoom.
FIX-001 is closed for its Attack scope. At the original FIX-002 report Safari still zoomed at other positions;
the exact failing non-Attack locations/device version were not supplied.
The table identifies actual runtime policy gaps, not individually reproduced
Safari failures. No phone model, iOS/Safari version or device FPS is inferred.

| Surface | Before FIX-002 (measured computed styles) | Hit testing / final policy |
|---|---|---|
| Game container / canvas | `auto` / `auto` | Canvas or container receives empty-world taps; now `none` plus scoped touch-end fallback |
| Joystick ring / knob | `none` / `auto`; knob pointer-events none | Ring owns pointers; all descendants now explicitly `none`, fallback on ring |

| Zoom output / status / combat HP/text | `auto`, inherited pointer-events none | Events pass through to gameplay canvas; no new clickable overlays |
| Recover | `manipulation`, native click handler | Retain manipulation; native tap-click compatibility below |
| Portrait rotate overlay | `auto`, pointer-events auto | Now `none` and scoped fallback; no orientation locking |
| Ordinary webpage, links, fields | Not game controls | Unchanged; guard excludes links/fields/contenteditable, and rejects targets outside game root |

The viewport meta stays `width=device-width, initial-scale=1.0, viewport-fit=cover`.
No user-scalable=no or maximum-scale limit. Body and outside content remain
`touch-action:auto`. Canvas deliberately owns gestures; browser pinch/zoom outside
the dedicated gameplay area is not disabled. Existing CameraController handles
wheel/+/- zoom and is unchanged. Browser page scale and camera zoom are separate.

## Implementation

- `public/style.css`: explicitly scope `none` to canvas/container, joystick and
  portrait prompt; `manipulation` to Zoom/Recover and their descendants; decorative
  descendants do not steal pointer hit tests. Attack FIX-001 CSS is untouched.
- `game/GameGestureGuard.ts`: one Scene-owned guard attached to the local game
  container after map setup. Delegated touch-end cancellation uses an explicit
  allowlist. It never prevents defaults on document/window, never registers a
  click/pointer/wheel action handler, and never changes camera/input/combat state.
  Attack is excluded from this guard and retains FIX-001.
- Canvas, joystick and Zoom already use Phaser/Pointer Events for actions;
  canceling their touch-end defaults adds no duplicate activation or camera step.
- Recover requires a native click. Canceling touchend would suppress that click,
  so the guard restores exactly one `button.click()` for an owned, enabled,
  visible, uncanceled tap ending inside the same button. Maximum travel is 10 CSS
  pixels (tap slop, not time debounce). Movement/outside release/cancel/blur/hidden
  tab/pause/sleep drops pending activation. A second touch cannot steal ownership.
  Prior event cancellation is respected. Native mouse, Enter and assistive clicks
  remain attached to the existing button handler. No synthetic clicks for Zoom
  or Attack. No native game action is throttled or queued by this guard.
- Start/move observers are passive; only the scoped touchend fallback is
  non-passive. All four root listeners, blur/visibility observers and Scene hooks
  are removed on shutdown/destroy. No global gesture-cancel listener exists.

DOM markup, TouchControls, CameraController, CombatController, viewport meta,
movement, projection and combat cooldown remain unchanged by FIX-002.
